# Roadmap — AI test-case generation tool

Goal: close the full testing life cycle in one tool — **map → generate → execute → diagnose → repair → expand** — with AI doing the heavy lifting at every step.

Agreed 2026-10-06 (re-ordered the same day: cases layer before triage). Order matters: each phase makes the next one trustworthy.

## Already shipped
- `/navmap` exploration with uiRegion components, map canvas, live headless exploration from the UI (new project / Explore more).
- Coverage tab, POM classes, fixtures + per-user page wrappers (Guest/Auth users), precondition linking (chained tests).
- Settings tab (execution + agent model/budget per project).
- One folder per project: `projects/<id>/` (reset = delete the folder).

## Architecture decision (2026-10-06): three separate layers
Until Phase 2 the map *was* the test suite (1 action = 1 test, regenerated from `navmap.json`), which overloaded `/navmap` and left no place to store a fix, a journey or a negative case. From Phase 3 on:

| Layer | Owner | AI? | Writes |
|---|---|---|---|
| **Discovery** — pages, actions, locators, observed facts (`check`, `formFields`, `destructive`, `anchor`) | `/navmap` skill (explorer) | yes | `navmap.json` (+ snapshots). Only maps; never creates or touches cases. Re-exploration adds/corrects facts. |
| **Test design** — scenarios with steps, data, expected results; lifecycle draft → approved | new test-design skill (agent) | yes | `projects/<id>/cases/*.json` |
| **Automation** — Playwright code | generator (plain code) | no | `tests/`: POMs from the map, specs only from approved cases |

Rules:
- **Locators live only in the map.** Case steps reference map actions by edge id (→ POM methods); expected results reference observed `check`s. The design agent never writes locators or code.
- **Reuse is automatic:** a missing action is discovered and added to the map → the generator creates its POM method → every case can use it. Cases can use other cases as preconditions (replaces `precondition-links.json`).
- **Nothing is added on its own.** Map changes never create cases: a case whose action disappeared is flagged "needs review"; a new action shows as "no case" in the Cases tab.
- **When it runs:** explorer from the Map tab; design agent from the Cases tab (scope: page / action / project / free text, or "Design cases here" from the map) — only on request, costs quota; generator automatically on every case approve/edit or map change (free, diff banner shows what changed).
- **Minimum context for the design agent:** a plain-code prompt builder sends a scoped slice — target page (URL, actions, form fields, checks, existing POM methods), the shortest route from start (incl. login), neighbor page names/actions, existing case titles — not the whole map.
- **Filling gaps, cheapest first:** (1) compose from existing map actions, no browser; (2) read the page's saved accessibility snapshot; (3) targeted browser — follow the map route, perform the precondition, observe, and merge the new action/observation into the map (mini-exploration). Run traces are left for triage.

## Phase 3 — Test-case layer + test-design agent
- [x] **3a. Cases layer** (no quota) ✅ 2026-10-06: `projects/<id>/cases/<caseId>.json` (steps → edge ids with item/input/form overrides, which observed checks to assert, and expected values for text/count checks — e.g. cart badge "1", "2", "3"; `requires` = case-as-precondition; status draft/approved/rejected; "needs review" derived when the map changes under a case). Baseline drafts (`base-<edgeId>`) reproduce the old 1-action-per-edge suite byte-for-byte apart from the annotation. **Test cases** tab: empty state (Create drafts / Create & approve all / build by hand), per-page approve, "actions without a case", case modal with editor (+ Add step from actions available where the previous step leaves you), Code tab with preview for drafts. Specs only from approved cases; code regenerates automatically after every case/flag/user/link/exploration change. Runs, history and heatmap keyed by case (old runs map to their baseline case). CLI: `npm run navmap:cases:baseline -- <id> [--approve]`.
  - Kept as is for now: `edge-flags.json` (destructive is a fact about the action) and `precondition-links.json` (still resolves the first step's preconditions) — links stay for baseline cases; the designer expresses setup as explicit steps or `requires`, so moving links is no longer needed.
  - Known limits: a journey can't switch users mid-test (a guest case that logs in can't continue on auth-only pages — start it as the auth user instead); choosing a list item isn't supported on shared component actions.
- [x] **3b. Accessibility snapshots** ✅ 2026-10-06: one per page in `projects/<id>/snapshots/<pageId>.yml` (gitignored, beside the map — no schema change). Captured by `/navmap` on arrival (before typing anything), and by a free deterministic refresh (`npm run navmap:snapshots -- <id>` / "📸 Refresh page snapshots" on the Map tab) that visits each page by URL, renews expired sessions like the fixtures, and only saves when it really arrived (URL + landmark). Credentials scrubbed after every exploration and refresh. `readPageSnapshot()` strips live-session markers for prompts; the map side panel shows each page's snapshot. Saucedemo: 10/10 pages, ~9 KB total, prices and "Item total" present.
- [x] **3c. Test-design agent** ✅ 2026-10-06 — validated by a real run (login page, no request: 4 useful drafts incl. a newly recorded failed-login action; user approved and they passed): `/navmap-design-cases` skill with plain-code helpers (`navmap:design-context` — compact JSON with routes from the entry page; `navmap:snapshot`; `navmap:save-design` — validates, dry-runs the real generator, saves nothing on errors). Map gained **page elements** (`PageNode.elements`: prices, totals… with optional per-item scope, `source: snapshot|browser`) → page-object locators/getters. Cases gained **`capture`/`verify`** (literal, captured value, or `equalsSumOf`), generated with `readAmount`/`readText` + `toBeCloseTo`. "✨ Design cases" panel (scope + optional request, live browser view, log). Designer model/budget in Settings. Shares the explorer's live browser (one browser agent at a time).
  - Acceptance scenario staged by hand through `save-design` (no quota): prices captured on the catalog, each line price + Item total = sum checked on the overview — **passes**; with a wrong sum it fails with "Item total = backpackPrice + bikeLightPrice · Expected: 39.98".
  - Acceptance scenario (from the user, 2026-10-06): saucedemo — "add 2–3 products; in the checkout overview each price matches the catalog and Item total = their sum". Needs what the map lacks today (price/total elements, found via the 3b snapshot, not a hand-built plan per locator) plus value capture/compare in cases (capture on one step, compare/sum on a later one). Deliberately NOT built by hand in 3a — it's the test of whether 3b+3c fill gaps on their own.
- [x] `/navmap` skill trimmed back to mapping only (it states it never creates cases; real-input-only rule).

## Phase 4 — Triage + self-repair agent ✅ 2026-10-06 — validated by real runs (user triaged the X and LinkedIn failures, approved the verified fixes, suite all green)
- [x] **Free rule-based hint** on every failed test in the run detail (no AI): environment / session / locator-missing / locator-ambiguous / navigation ("new tab?") / assertion, with "▶ Rerun (free)" when a rerun is the sensible first move. Checked against every real failure on disk.
- [x] **`/navmap-triage` agent** (🩺 per failure or "Triage all"): `navmap:triage-context` gives the error, the generated test, the case's steps with the map facts they use, and the page's aria snapshot at failure (Playwright's error-context.md, now kept per run and scrubbed); it may reproduce in the live browser (real input only, nothing destructive). Classifies app bug / test bug / environment.
- [x] **Fixes in the right layer, never applied by the agent**: `navmap:save-triage` validates a proposal on copies (map fact: locator/scope/external/postconditions/anchor/element; or the case's steps). The dashboard **auto-verifies** it (apply temporarily → run that one test → always restore), shows the diff + "✓ passed with the fix / ✗ still failing", and the user approves (drift-checked; map fixes get `lastRepair`, shown in the map side panel) or rejects.
- Pipeline proven without quota: saucedemo "Open Facebook" (`opensNewTab: false` → true) verified ✓ and approved, test green; a deliberately broken "Open cart" locator → map fix verified ✓ and reverted. Triager model/budget in Settings; shares the live browser (one browser agent at a time).
